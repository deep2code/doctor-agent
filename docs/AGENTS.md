# docs — 背景说明，不是权威清单

**重要文件的职责现在写在每个目录的 `AGENTS.md` 里**（`internal/*/AGENTS.md`、`cmd/`、`evals/`、`external/`、`docker/`、`internal/server/web/`），改代码时那些文件会被就近读到。本目录只放叙述性的架构背景和专题设计草稿。

| 文件 | 作用 | 与代码的关系 |
|---|---|---|
| `architecture.md` | 图文架构：管线分层、模块依赖、数据流、部署拓扑 | 叙述可用，但**具体行号与数量以代码和目录文档为准** |
| `architecture.html` | 同一份内容的网页版（图示） | 同上，改动不会自动同步，改了 md 要手工同步 |
| `symptom-synonyms.md` | 症状同义词/口语映射的**设计草稿** | 文件头部已自我声明"运行时以 `internal/knowledge/alias_map.json` 为准"；两者不冲突，别把这份当运行时配置读 |

## 维护约定

- 与代码冲突时，以代码为准并**立刻回头改文档**（这是用户的长期要求：AGENTS.md/README 必须与代码保持事实一致）。
- 数字类陈述（条目数、数据集数、归档数、镜像 tag）最容易过期：能写成"如何测出来"（命令）就不要写成"是多少"。
- 新增架构性决策文档放这里；一次性的调试笔记、事故复盘写进根 `AGENTS.md` 的 Notes 一节（那里是决策历史，不是文件清单）。
